### `display: flex` lays out a row, and items shrink by default

`flex-direction` used to default to `column` everywhere and `display: flex` changed nothing, so a
stylesheet written for the web laid its flex rows out as columns. The default now follows `display`
the way a browser's does: an element with no `display`, or with `display: block`, stacks its
children, and `display: flex` or `inline-flex` lays them out in a row. `block`, `inline-block` and
`flow-root` are recognised values; there is no block layout here, so all of them are flex containers
that stack. Tailwind's `block`, `flex`, `flex-row` and `flex-col` now do what they do on the web.

An element that declares `display: flex` without a `flex-direction` and meant a column needs
`flex-direction: column`, or the `display` removed. Nothing else changes, since `display: flex` used
to be a no-op.

`flex-shrink` defaults to 1 as on the web, so an item gives up space before it overflows its
container. The `flex` shorthand fills in the web's values too: `flex: 1` is `1 1 0%` where it used
to be `1 0 auto`, a bare basis such as `flex: 30px` is `1 1 30px`, `flex: auto` is `1 1 auto` and
`flex: none` is `0 0 auto`. To keep the old default, write an author rule — but leave `scroll` and
`dialog` out of it, since both rely on shrinking:

```css
*:not(scroll):not(dialog) { flex-shrink: 0 }
```
