### `position: sticky` and `position: fixed`

Both values have been in the `PositionType` enum since 2021 and neither did anything: `fixed` fell
through to `absolute`, and `sticky` fell through to `relative`, so its insets shifted it in flow —
the one thing sticky must never do. Both are implemented for UGUI now.

```css
.header { position: sticky; top: 0; }
```

A sticky box keeps its place in flow and is then shifted the least it can be to stay inside the
nearest scroll container shrunk by its own insets, then clamped to its parent's content box — so it
is pushed back out at the end of a section the way a heading is. Its siblings never move for it, and
it follows the scroll in the same frame rather than a `motion-duration` behind it. An element with
no scrollable ancestor is not shifted at all.

A fixed box is positioned against the host — the same box `vw` and `vh` measure — and is lifted out
of its parent, so an ancestor's `overflow: hidden` no longer clips it. Two consequences of the lift
differ from a browser and are deliberate: a lifted element no longer inherits an ancestor's
`opacity`, `transform` or `filter`, and with no insets it lands at the viewport origin rather than
at its static position.

### `scroll-state(stuck: ...)`

The feature parsed and never held, because nothing was ever sticky. It now asks which edges of its
scrollport are holding the container, taking the same values `scrollable` does. Like `scrollable` it
is read off the container itself, so the sticky element carries `container-type: scroll-state` and
the rules inside style what it contains.

```css
.header { position: sticky; top: 0; container-type: scroll-state; }

@container scroll-state(stuck: top) {
  .header .title { font-size: 14px; }
}
```

`snapped` still parses and never holds.

### UIToolkit: an unpositioned element was taken out of flow

`position: static` was read as `absolute` there, so an element asking for the plainest possible
in-flow placement got the opposite. `static` and `sticky` are now `relative`, and `fixed` joins
`absolute`. UIElements has neither a sticky nor a viewport-relative position, so a sticky element
under UIToolkit sits at its in-flow position with its insets suppressed, and a fixed one behaves as
`absolute`.

`Positioning` is a new page in the Kitchen Sink sample, covering both.
