### Accept the CSS that Tailwind and the web actually emit

Each spelling below was silently dropped before. Each is now either honoured or mapped onto the
nearest thing the renderer already had.

**Names and keywords.** Vendor prefixes are stripped, so `-webkit-line-clamp` is `max-lines` and
`-webkit-text-stroke` is `text-stroke`. `text-decoration-line` sets the same flags as `font-style`.
`overflow: auto` scrolls and `overflow: clip` hides. `font-variant: small-caps` and its relatives
are a `text-transform`. `text-align` takes `justify`, `start` and `end`; `text-overflow` takes
`clip`; `text-wrap: balance | pretty | stable` parse as plain wrapping. The `dvh`/`svh`/`lvh` family,
`dvw`/`svw`/`lvw`, their `min`/`max` forms and `vi`/`vb` all resolve as viewport lengths.

**`min()`, `max()` and `clamp()`** work anywhere `calc()` does, with the same operand grammar. `none`
is accepted for either bound of `clamp`.

**`white-space`** carries `pre`, `pre-wrap`, `pre-line` and `break-spaces`, so runs of spaces and
newlines are preserved where the value asks for it. `text-wrap: nowrap` used to be the whole story.

**`text-shadow`** is drawn through TextMeshPro's underlay, so no second text object exists and
`1px 1px 2px` looks the same at any font size. TMP has a single underlay, so only the first shadow
of a list is drawn.

**`overflow-x` and `overflow-y`**, with `overflow` as a two-value shorthand over them. Yoga has one
overflow, so it gets the stronger of the two and the mask applies when either axis is hidden. What
the split buys is scroll direction: a `<scroll>` with `overflow-x: hidden` scrolls vertically only.

**`caret-color` and `::selection`** on `<input>`. The caret defaults to `currentColor`. `::selection`
is a pseudo-element like `::placeholder`, and its `background-color` is the input's selection
highlight. That is the whole of what TextMeshPro can recolour: the selected glyphs keep their own
colour, and `<text>` has no selection at all.

**`scrollbar-color` and `scrollbar-width`** on a `<scroll>`. They are read by the user-agent
`::scrollbar` and `::scrollbar-thumb` rules through `var()`, so a `::scrollbar` rule of your own
still wins. `none` is a zero-size scrollbar rather than `display: none`. Both inherit, where the
spec inherits only the colour.

**Media queries.** `prefers-color-scheme` and `prefers-reduced-motion` exist as features. The default
scheme follows the Editor skin in the Editor and is `light` in a player; reduced motion defaults to
`no-preference`. Set either with `DefaultMediaProvider.SetValue`.

**Gradients** parse `linear-gradient(to right in oklab, …)` and the same hint on `radial-` and
`conic-gradient`. The colour space is not honoured; interpolation stays in sRGB.
