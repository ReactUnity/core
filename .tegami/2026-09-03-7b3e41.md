### A Vite preset for ReactUnity apps

`@reactunity/renderer/vite` configures Vite the way a ReactUnity app needs it, so a project's whole
config is:

```ts
import reactUnity from '@reactunity/renderer/vite';
import { defineConfig } from 'vite';

export default defineConfig({ plugins: [reactUnity()] });
```

- **Output goes into the Unity project**, at the `Assets/Resources/react` of the project it finds by
  walking up from the Vite root. Both layouts are found, the app inside the project and the app
  beside it; `unityProject` and `assetPath` say it outright when the guess is wrong.
- **`.meta` files survive the clean**, so a rebuild keeps the GUIDs that scenes and prefabs point at,
  and a failed build leaves them for the next successful one to restore. `preserve` exempts paths
  the build does not own.
- **Filenames carry no content hash**, for the same reason: a hash renames the file on every build
  and costs it its meta. `hashFileNames: true` restores Vite's naming.
- **Emitted assets carry their extension twice**, so `index.css` is written as `index.css.css`.
  Unity finds a resource by its path minus the last extension, which would otherwise make
  `assets/index.js` and `assets/index.css` the same resource.
- **Assets are never inlined**, since Unity loads an asset url through its own loaders and an
  inlined one stops resolving.
- **CSS targets `chrome87`**, so Lightning CSS lowers `oklch()`, `color-mix()` and nesting on the
  way out.
- **Vite's devtools and the HMR error overlay are off.** Neither has anywhere to draw in Unity.

Everything the config sets itself wins — the preset only fills in what was left out — and
`react: false` drops `@vitejs/plugin-react` for a project that wants to configure React itself.
