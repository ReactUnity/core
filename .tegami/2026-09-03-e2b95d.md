### @layer

**Cascade layers work.** `@layer` groups rules into named layers whose order you decide, and that order is consulted before specificity — which is how a framework's `#id` rule can be made to lose to your own `text` rule without an `!important` anywhere. All the declaration forms are here: a block, a bare `@layer name;`, a list (`@layer a, b, c;`), an anonymous block, sub-layers by nesting or by dotted name, and layers inside `@media` and `@supports` in either order.

The ordering is CSS Cascade 5's. A layer takes its place from where its name is first seen, so reopening one adds to its original position rather than moving it to the end; unlayered rules beat every layer; a later layer beats an earlier one; a sub-layer sits inside its parent's slot and loses to the parent's own rules; and `!important` reverses the first two. A `@media` condition flipping at runtime never reshuffles the order, because layer positions are settled from the source before any rule is indexed.

Layers are scoped to one stylesheet, unlike in a browser where every sheet in the document shares one set of them. So the same name in two sheets is two unrelated layers, and the sheets themselves order relative to each other the way they always did. A stylesheet has room for 30 distinct layer positions, sub-layers included; past that they share the last one. `revert-layer` is not implemented, and `@import` was never supported, so `layer()` on one has nothing to attach to.

Existing stylesheets are unaffected. Layer rank is packed into the same specificity integer, between importance and the selector's own specificity, and everything unlayered keeps its relative order exactly.

**The bundled CSS parser moved to ExCSS's current source**, which is where `@layer` comes from — it landed upstream in August 2026, after the 4.3.2 release. It is built by `pnpm build:excss` from a pinned commit of our fork, whose first commit is a parser option that hands over each declaration's name and value exactly as written. Stock ExCSS resolves every declaration to a typed property, normalises the value and expands shorthands into web longhands, which would quietly bypass ReactUnity's own shorthand layer — where `flex: 0` means grow 0, shrink 0 and an auto basis, and `motion`, `audio` and `text-stroke` have no web counterpart at all. The binary that shipped before this had the same behaviour patched in without a record of it; now it is a commit with tests on a branch anyone can read, and `PROVENANCE.md` sits next to the DLL.

**On Tailwind v4.** `@layer theme, base, components, utilities` is what its output opens with, and every rule it emits lives inside one of those four — so until now none of them reached the styling layer at all, whatever else worked. That was the last of the three things standing between its generated CSS and this renderer; with the color functions from the previous entry and the nesting support from the next one, a Tailwind v4 stylesheet parses and cascades as written.
