### A code-split bundle loads out of `Resources`

**A lazy route's chunk now resolves.** A bundle read out of `Resources` had only the resource path
it came from, which is relative, so the first dynamic `import()` failed with
`Could not resolve module './chunk.js'`. Those modules get an origin of their own,
`resource:///assets/index.js`, and all three engines read that scheme back through `Resources.Load`.

**The entry is registered under that url**, so a chunk importing it back gets the module already
there. It used to read the bundle again and evaluate a second copy of it, leaving two renderers
holding two sets of callbacks while the C# side had ids for only one — so the first click on
anything reported `TypeError: cannot read property 'apply' of undefined`, with nothing to say a
module had been loaded twice. The WebGL backend shares the fix.

**`Event` is a global.** Bundler output reports a failed chunk by dispatching one and reading
`defaultPrevented` to decide whether to rethrow, as Vite's dynamic-import wrapper does, so a chunk
that failed to load reported `Event is not defined` and the real reason was lost. `dispatchEvent`
now takes either an event or the type it has always taken. Only the event's own members are there,
there being no tree for it to travel through.
