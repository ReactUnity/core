### Soft masks, `clip-path`, and `image-rendering: pixelated`

**`mask-image` was one bit deep and is now real coverage.** A mask was built as a UGUI `Mask`, which
is a stencil, so the fade that every `linear-gradient(black, transparent)` mask is written for came
out as a hard edge or as nothing at all. Masks are now drawn to a texture of their own and
multiplied into the element's alpha, so a gradient mask fades, a soft-edged sprite has soft edges,
and a semi-transparent mask leaves the element semi-transparent.

```css
mask-image: linear-gradient(black, transparent);
mask-image: radial-gradient(circle at center, black 40%, transparent 70%);
```

Layers add, which is CSS's default `mask-composite: add`. The other three composite operators are
still unsupported. `mask-mode` and its synonym `mask-type` choose the channel: `alpha`, the default
and what `match-source` resolves to, or `luminance`, where the mask's brightness is the coverage.
The `mask` shorthand carries a mode like every other component.

**`clip-path` is new**, with the four basic shapes:

```css
clip-path: inset(10% 20% round 24px);
clip-path: circle(farthest-side at 25% 75%);
clip-path: ellipse(50px 30% at center);
clip-path: polygon(50% 0%, 100% 38%, 82% 100%, 18% 100%, 0% 38%);
```

Shapes are antialiased over one device pixel, so a curve or a diagonal comes out smooth and a circle
stays round however oblong the element is. Values are resolved against the box each frame, so a
percentage shape follows a resize and `calc()` inside one works. Two shapes of the same kind
interpolate, so a shape animates; different kinds, a changed extent keyword and a changed vertex
count are discrete, as CSS specifies. `polygon()` takes an optional `nonzero`/`evenodd` fill rule
and up to sixteen points. A geometry box keyword parses and is ignored — everything is measured
against the border box.

A clip also **changes where the element can be clicked**, which is the difference between a clip and
a mask: a pointer landing outside the shape passes through to whatever is behind it. `mask-image`
deliberately does not do this, matching CSS.

Both land in the order CSS composites them: the filter chain runs, then the clip, then the mask,
then `opacity`. So a `drop-shadow()` is clipped and masked along with the element that cast it. An
element that masks or clips becomes a blending group, so a descendant's `mix-blend-mode` stops
there. `mask-image: none` and `clip-path: none` cost nothing.

**`image-rendering` is new**, and the value that does something is `pixelated`:

```css
image-rendering: pixelated;
```

The sample is snapped to the nearest texel centre, so a 16×16 sprite drawn at 160×160 shows sixteen
crisp squares per side instead of a bilinear smear. It applies to `<image>` and `<rawimage>`, to
`background-image` layers and to `mask-image` layers; `crisp-edges` is the same thing, and `smooth`
and `high-quality` are accepted and mean `auto`. The property is inherited, so setting it on a
container covers the images inside it.

This is done per element rather than by setting the texture's `filterMode`, which belongs to the
imported asset — so one element asking for crisp edges no longer changes every other element drawing
the same image, or leaves it changed in the editor. It has no effect on a gradient or an SVG.
