### Soft masks, `clip-path`, and `image-rendering: pixelated`

**`mask-image` was one bit deep and is now real coverage.** A mask was built as a UGUI `Mask`, which
is a stencil, and a stencil bit is either set or not — so the fade that every `linear-gradient(black,
transparent)` mask is written for came out as a hard edge at the alpha clip threshold, or as nothing
at all. Masks are now drawn to a texture of their own and multiplied into the element's alpha, so a
gradient mask fades, a soft-edged sprite has soft edges, and a semi-transparent mask leaves the
element semi-transparent.

```css
mask-image: linear-gradient(black, transparent);
mask-image: radial-gradient(circle at center, black 40%, transparent 70%);
```

Layers **add**, which is CSS's default `mask-composite: add`, and it falls out for free: the layers
are painted over transparent black with ordinary source-over blending, and source-over alpha is
commutative. The other three composite operators are still unsupported — each is a fixed-function
blend state, which conflicts with the per-image materials gradients need.

`mask-mode` and its synonym `mask-type` choose the channel: `alpha` (the default, and what
`match-source` resolves to, there being no SVG `<mask>` to read a mode off), or `luminance`, where
the mask's brightness is the coverage. The `mask` shorthand carries a mode like every other
component.

**`clip-path` is new**, with the four basic shapes:

```css
clip-path: inset(10% 20% round 24px);
clip-path: circle(farthest-side at 25% 75%);
clip-path: ellipse(50px 30% at center);
clip-path: polygon(50% 0%, 100% 38%, 82% 100%, 18% 100%, 0% 38%);
```

Shapes are evaluated as signed distance fields in the element's own box, antialiased over one device
pixel — so a curve or a diagonal comes out smooth, and a circle stays round however oblong the
element is. Values are kept as written and resolved against the box each frame, which makes a
percentage shape follow a resize and lets `calc()` inside one work. Two shapes of the same kind
interpolate, so a shape animates; different kinds, a changed extent keyword and a changed vertex
count are discrete, as CSS specifies. `polygon()` takes an optional `nonzero`/`evenodd` fill rule and
up to sixteen points; a longer list is cut rather than refused. A geometry box keyword parses and is
ignored — everything is measured against the border box.

A clip also **changes where the element can be clicked**, which is the difference between a clip and a
mask: a mask paints, a clip changes the element's shape. A pointer landing outside the shape passes
through to whatever is behind it. `mask-image` deliberately does not do this, matching CSS.

Both ride the offscreen capture `filter` and `mix-blend-mode` already use, and land in the order CSS
composites them: the filter chain runs, then the clip, then the mask, then `opacity`. So a
`drop-shadow()` is clipped and masked along with the element that cast it, and `opacity` fades what
survives rather than being masked itself. The consequence is the same one the other capture
features have — an element that masks or clips becomes a blending group, so a descendant's
`mix-blend-mode` stops there. `mask-image: none` and `clip-path: none` tear the capture down again
and cost nothing.

**`image-rendering` is new**, and the value that does something is `pixelated`:

```css
image-rendering: pixelated;
```

The sample is snapped to the nearest texel centre, so a 16×16 sprite drawn at 160×160 shows sixteen
crisp squares per side instead of a bilinear smear. It applies to `<image>` and `<rawimage>`, to
`background-image` layers, and to `mask-image` layers; `crisp-edges` is the same thing, and `smooth`
and `high-quality` are accepted and mean `auto`. The property is inherited, as on the web, so
setting it on a container covers the images inside it.

This is done in the shader rather than by setting the texture's `filterMode`, which is what keeps it
a per-element property: a `Texture2D`'s filter mode belongs to the imported asset, so one element
asking for crisp edges would change every other element drawing the same image — and, in the editor,
keep it changed. It has no effect on a gradient, which is generated at the size it is drawn at, nor
on an SVG, which is geometry rather than a raster.

**A translucent draw's coverage was being squared in a render target**, which had to be fixed before
any of this could be exact. ReactUnity's own UI shaders declared `Blend SrcAlpha OneMinusSrcAlpha`,
which applies that factor to the alpha channel as well — so drawing something 50% opaque into a
target that started transparent left 25% behind, not 50%. Nothing on screen showed it, because the
back buffer's alpha is never read; a mask layer and the filter capture are exactly the targets where
it does show. `BackgroundImage`, `BackdropFilter` and the new `PixelatedImage` shader now use
separate alpha blending — `Blend SrcAlpha OneMinusSrcAlpha, One OneMinusSrcAlpha` — the way UGUI's
own default UI shader already does. A gradient background inside a filtered element was mis-composited
by the same amount, since the composite unpremultiplies by that alpha; that is fixed too.

Mask ownership moved out of `BorderAndBackground` in the process. It has no `MaskGraphics` or mask
root any more; the composite owns the layers, because it is the only thing that can sample them.
