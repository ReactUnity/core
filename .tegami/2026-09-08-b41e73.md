### The generated Typescript models are current again, and regenerating them is one command

`packages/renderer/src/models/generated/*.ts` had not been regenerated since January 2025, because
regeneration meant a human clicking a menu item in an open Editor. `generate_models` is a
`[CliCommand]` now, so `unity command generate_models -- --directory … --preset all` writes the
whole set against a running Editor, and the models track the C# they describe.

All six files are regenerated, which is a year of Unity API movement plus everything ReactUnity has
added since. They are one matched set -- `react.ts` and `editor.ts` import Unity's own types from
`unity.ts` -- so they have to be written together; regenerating one alone leaves references nothing
declares. `UnityEngine.LightTransport.InputExtraction+BakeInput` is excluded to `any` for the mirror
image of that problem: it is declared in an editor assembly but sits under the `UnityEngine`
namespace, which the namespace-to-file mapping sends to `unity.ts`, where nothing declares it.

The command's assembly is gated on `REACT_UNITY_DEVELOPER` and on `com.unity.pipeline`, so it does
not ship.
