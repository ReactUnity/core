### The bundled CSS parser reads @container and @starting-style itself

Until now a stylesheet was rewritten before parsing: every `@container` and `@starting-style` block was dressed as a `@media` with a marker prelude, because the parser dropped a `@container` nested in a style rule, read its prelude through the media grammar, and had no `@starting-style` rule at all. The ReactUnity fork of ExCSS now parses both as their own rules, at the top level and nested in a style rule, and keeps a `@container` prelude as written, so the range syntax and `style()` queries reach the query engine untouched. The rewrite and its markers are gone; `insertRule` and `appendRule` take the plain CSS too. The parser also accepts `:where()`, as `:is()` with zero specificity, which matches how the selector engine already treated it.

The fork now lives at [ReactUnity/ExCSS](https://github.com/ReactUnity/ExCSS) and is checked out as the `vendor/excss` submodule, which is where the built binary's commit is pinned.
