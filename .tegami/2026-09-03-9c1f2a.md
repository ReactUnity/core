### A Vite entry document no longer crashes the editor, and its stylesheets now apply

**The crash.** Pointing a scene at a Vite dev server took the Editor down with an access violation, and the reason is worth stating because the same shape can bite any host binding. QuickJS evaluates a module by walking the graph depth-first, threading the traversal's stack through a field on each module — one field, shared by every traversal in flight. Overlap two of them and they splice each other's chains; the second to finish pops until it reaches the module it started from, does not find it, and walks off the end into a null pointer.

They overlapped because the job pump was reentrant. A queued job can evaluate a module, and any C# binding that reaches back into the engine can end up pumping from inside one — `document.querySelectorAll` marshals its result by evaluating a script, and Vite's HMR client calls it at module scope. `ScriptRuntime.ExecutePendingJob` now refuses a nested call; the pump already on the stack drains whatever the nested code queued, so nothing is lost. The same guard is in the native library as well, in `JS_ExecutePendingJob`, so an embedder cannot reach the bad state through a path the C# layer does not cover. That is a fork change — `gkurt/quickjs` `v0.16.2-reactunity.2` — and every shipped binary is rebuilt from it.

**The preamble race.** An entry document with more than one script used to evaluate all of them at once, which is not what document order means. Vite's dev server inlines the React Refresh preamble and then loads the app, and the app checks for what the preamble installs — evaluated concurrently, it could look before the preamble had written. Host-initiated module roots are now evaluated one at a time, in document order. A graph that never settles will hold up the ones behind it; a graph that rejects settles normally.

**Stylesheets in the entry document.** `<link rel="stylesheet">` and `<style>` were dropped on the floor, which is why a built Vite project came up completely unstyled — the built `index.html` links its CSS and nothing else mentions it. Both are now collected in document order, so the cascade survives, and applied at `:root` so they reach the whole tree rather than the node they were declared on. `preload`, `modulepreload` and `alternate stylesheet` are skipped, matching what a browser applies.
