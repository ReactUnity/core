### CSS nesting, :is(), :where() and escaped class names

**A style rule can contain other style rules**, so the enclosing selector no longer has to be repeated on each one. `&` stands for it and may sit anywhere in the nested selector; without `&`, the nested rule matches a descendant. Selector lists nest across every branch, nesting goes as deep as you like, and each rule's own declarations still apply to what that rule matches.

```css
#panel {
  background-color: black;
  text { color: white; }
  &:hover { background-color: #222; }
  > .header { padding: 10px; }
}
```

**`@media` and `@supports` nest inside a style rule too.** The declarations directly inside one belong to the enclosing selector, so `#panel { @media (min-width: 600px) { padding: 20px } }` is `@media (min-width: 600px) { #panel { padding: 20px } }`, and rules nested inside the condition resolve against the same selector. Previously the condition was discarded and its declarations were left looking unconditional; now the block is either applied or not, as written. An at-rule that cannot nest here — `@container`, which has no support at all — is ignored, and the declarations around it are unaffected.

**`:is()` works**, both because a resolved nested selector is built out of it and on its own account. It is rewritten to one selector per argument, so its specificity is the matching argument's rather than `:is()`'s rule of taking the most specific one; that only shows up when the arguments differ, as in `:is(.a, #b)`. Two forms match nothing rather than being guessed at: an `:is()` mid-compound whose argument spans a combinator (`.x:is(.a .b)`), and an `:is()` inside another functional selector (`:not(:is(.a, .b))`), where a list means *all of* instead of *any of*.

**`:where()` works too**, matching whatever `:is()` would while adding no specificity of its own — so one class outranks a `:where(#id)` rule, where an `:is(#id)` would have won. Everything in the parentheses is discounted, however many compounds it spans, an `:is()` in there included. The two forms `:is()` is not rewritten in are not rewritten here either.

**Escaped class names round-trip.** `.hover\:underline`, `.w-1\/2` and the hexadecimal form a leading digit forces, `.\32 xl\:flex`, all match the class they name, nested selectors included. The escapes were being resolved while reading and then written back out plain, which turned `.hover\:underline` into `.hover:underline` — a class followed by an unknown pseudo-class — and quietly destroyed every rule nested inside one.

A comma inside `:is(…)`, `:not(…)` or an attribute value is also no longer mistaken for the end of a selector in a list.

Two fixes in the bundled CSS parser were needed for this: the nested conditional rule, and resolving a nested selector against the text a rule was read from rather than its serialization, which is where the escapes were being lost. They join the raw-declaration option that predates them on the `reactunity` branch of [gkurt/ExCSS](https://github.com/gkurt/ExCSS), three commits ahead of upstream, each with its own tests and meant to go there. `pnpm build:excss` rebuilds the binary from the commit pinned in the script.
