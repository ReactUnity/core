### CSS nesting, `:is()`, `:where()` and escaped class names

**A style rule can contain other style rules**, so the enclosing selector no longer has to be
repeated on each one. `&` stands for it and may sit anywhere in the nested selector; without `&`,
the nested rule matches a descendant. Selector lists nest across every branch, and nesting goes as
deep as you like.

```css
#panel {
  background-color: black;
  text { color: white; }
  &:hover { background-color: #222; }
  > .header { padding: 10px; }
}
```

**`@media` and `@supports` nest inside a style rule too.** The declarations directly inside one
belong to the enclosing selector, so `#panel { @media (min-width: 600px) { padding: 20px } }` is
`@media (min-width: 600px) { #panel { padding: 20px } }`. The condition used to be discarded and its
declarations left looking unconditional. `@container`, which has no support at all, is ignored, and
the declarations around it are unaffected.

**`:is()` matches any of its arguments**, at the specificity of the one that matched rather than
`:is()`'s rule of taking the most specific one. **`:where()` matches the same and adds no
specificity of its own**, so one class outranks a `:where(#id)` rule.

**Escaped class names round-trip.** `.hover\:underline`, `.w-1\/2` and the hexadecimal form a
leading digit forces, `.\32 xl\:flex`, all match the class they name, nested selectors included. The
escapes were being resolved while reading and then written back out plain, which turned
`.hover\:underline` into a class followed by an unknown pseudo-class and quietly destroyed every
rule nested inside one.

A comma inside `:is(…)`, `:not(…)` or an attribute value is also no longer mistaken for the end of a
selector in a list.
