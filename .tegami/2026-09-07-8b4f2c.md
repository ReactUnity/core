### `filter` renders

`filter` has parsed since the property was added and applied to nothing, with no diagnostic. It
draws now, in the UGUI framework: `blur`, `brightness`, `contrast`, `grayscale`, `hue-rotate`,
`invert`, `opacity`, `saturate`, `sepia`, `drop-shadow`, and the non-standard `grain` and `pixelate`
that `backdrop-filter` already accepted.

The element's subtree is rendered offscreen and the result composited back into its original slot
with the filter applied. Unlike `backdrop-filter`, a filter only ever reads the element's own
pixels, so **it needs no per-pipeline code** and works under built-in, URP and HDRP alike — HDRP
being the one where `backdrop-filter` has never worked.

**An ancestor's `overflow: hidden` clips the filtered result, not the filter input**, which is what
CSS says. A mask *inside* a filtered element still clips.

**A filtered element stays interactive.** Pointer events are routed into the offscreen subtree and
back out, so an ancestor's `pointer-events: none` still applies, an ancestor's `overflow: hidden`
clips hits the same way it clips pixels, and an event nothing inside handled carries on bubbling up
the page.

**`rotate` and `scale` survive a filter**, and the chain runs in the element's local space as CSS
asks — so `pixelate` blocks turn with the element rather than staying screen-aligned, and a blur
radius widens with `scale`.

`drop-shadow` casts from the element's alpha, so it traces glyphs and transparent images instead of
the border box. It is taken after the element's own blur, which is the order `blur() drop-shadow()`
gives on the web, and the colour ops reach the element and not the shadow. It reuses `box-shadow`'s
parser, so it also accepts a spread and `inset`, both of which are ignored.

There is a filter region, as on the web, so nothing is sliced off at the edge.

What is not there yet:

- A filtered element wins a tie against unfiltered content drawn over it, depth between the two
  being settled by standing the subtree a hair in front rather than by real depth.
- `backdrop-filter: drop-shadow(...)` parses and does nothing. A backdrop has no alpha edge to cast
  from.
- UIToolkit has no `filter`. Nothing in Unity's own styling maps to it.

**A filtered element that is not changing costs nothing per frame.** It re-renders when the element
resizes, when a descendant graphic rebuilds, or when any descendant transform moves. A change to the
filter value only re-captures when the capture would come out different — a blur radius, or a
drop-shadow that moves or resizes the region — so animating `hue-rotate` or `brightness` costs one
material write per frame and no offscreen pass at all.

### Four more filter functions, aimed at game UI

`posterize`, `scanlines`, `tint` and `chromatic-aberration` join `grain` and `pixelate` as functions
the web does not have. All four work in `backdrop-filter` too.

`tint` multiplies, so it only darkens: `brightness(1.4) tint(#f66)` is the damage flash, and
`grayscale(1) tint(...)` is how a panel greys out. `posterize(n)` rounds to n evenly spaced levels
including both ends, so `posterize(2)` is black and white. The quantisation lands after the colour
ops and the tint and before grain and scanlines.

**Neither grain nor scanlines takes a time input.** Both take a trailing phase, and a `@keyframes`
animation on that is what moves them, which keeps a static filter free. A scanline pattern does not
move; its hum bar drifts, so the phase is a length and one period of it is one roll. Grain's phase
reseeds the noise instead, so it flickers rather than crawls, and the timing function picks the
rate: `linear` resamples every frame, `steps(12)` gives grain at twelve frames a second. `grain` was
static before this and had no way not to be.

Three of the four are pointwise and never re-capture the subtree. `chromatic-aberration` is the
exception, and widens the capture region the way a blur does — but in whole pixels, so animating one
through three pixels re-renders three times rather than sixty times a second.

### `style={undefined}` no longer takes the whole app down

A prop that is present and undefined is ordinary React, and `style` and `data` were the two that
could not survive it: reading one threw inside the command batch flush, which is an unhandled
promise rejection, so a single `style={cond ? x : undefined}` anywhere left the app with nothing
rendered and a Newtonsoft stack trace as the only clue. An undefined style now means no
declarations.

### `filter` and `backdrop-filter` are typed

Neither was in `Style`, so `style={{ filter: 'blur(4px)' }}` was a type error in every app while the
same declaration in a stylesheet was fine. Both are `SafeString` now, alongside `boxShadow` and
`textShadow`.

### Animating `backdrop-filter` no longer leaks a material per frame

`WebFilter` cached materials on a key that included the filter value, so every frame of a
`transition: backdrop-filter` produced a fresh `Material` that was never released, for the life of
the process. Each component now owns one material and mutates it in place. An all-identity filter
such as `brightness(1)` also stops allocating a render target for nothing.

### Applying a style that did not change no longer rebuilds the element

Three things an element's style assigns rebuilt their graphic whether or not the value had moved:
the background image's size, the border rounding, and TextMeshPro's font style, weight and font
asset. Nothing showed, because a rebuild produces the same pixels — it was paid for by every element
on screen, every frame. It is visible from `filter`, which re-captures a subtree when a descendant
graphic goes dirty: on the kitchen sink's filter page, four animated cards were re-capturing every
frame and three of them now hold one capture for the life of the animation.
