### QuickJS is now quickjs-ng, and modules load without blocking a frame

`com.reactunity.quickjs` binds [quickjs-ng](https://github.com/quickjs-ng/quickjs) in place of
unity-jsb's fork of Bellard-era QuickJS.

**`import` works.** A module graph is fetched while the engine keeps running, so importing an `http`
url — and therefore a dynamic `import()` — resolves without a blocking frame. `import.meta.url` is
populated on a fetched module, which is what the relative imports inside it resolve against. Ask
`EngineCapabilities.ModuleResolution` whether the engine in front of you can do this.

**WebGL can run modules for the first time.** ES module syntax simply did not work on that backend.
It now fetches a graph through the same loader and hands the linking to the browser, so live
bindings, top-level `await` and the module cache come from there. Circular imports are refused with
an error naming the cycle, and the page needs `unsafe-eval` and `blob:` scripts allowed.

**A runaway script throws instead of killing the process.** Infinite recursion used to take out the
player or the Editor with a `StackOverflowException` no `catch` could see; it now raises an ordinary
`RangeError`. `ScriptRuntime.MaxStackSize` sets the limit, which defaults to 768 KB — raise it for
deliberately deep code, and note that zero means ng's own default rather than no limit.

**An empty JavaScript string now marshals to C# as `string.Empty`, not `null`.** QuickJS was the one
engine that could not represent `''`. Drop any `?? ""` you wrote around a value arriving from
script, and check anywhere you branched on `null` to mean empty.

Operator overloading and the editor-side code generator are gone, and neither was reachable from a
Unity project. Reflection binding, which is what binds your types, is untouched.
