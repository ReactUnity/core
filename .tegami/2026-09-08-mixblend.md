### `mix-blend-mode`, and `isolation` grows a blending group

An element can blend into whatever is painted behind it, with all sixteen CSS blend functions —
`multiply`, `screen`, `overlay`, `darken`, `lighten`, `color-dodge`, `color-burn`, `hard-light`,
`soft-light`, `difference`, `exclusion`, `hue`, `saturation`, `color` and `luminosity` — plus
`plus-lighter`.

`plus-lighter` is not a blend function: the element is added to the backdrop and the sum is clamped,
which is how two overlapping glows brighten each other instead of the upper one winning. The
element's own opacity scales what is added rather than the result. CSS gives the keyword to
`mix-blend-mode` alone; here one enum backs both properties, so `background-blend-mode` parses it
too.

CSS blends an element **and everything inside it as one image**, and this matches: a card's
background, borders, text and children go into the backdrop together rather than each blending
against the ones drawn before it. Setting both `filter` and `mix-blend-mode` puts them in CSS's
order — the filter runs, and its result is what blends.

**`isolation: isolate` now creates a blending group.** A descendant that blends can only read the
backdrop the group hands it, and outside the group nothing changes. A `filter` on an ancestor
contains a blend for the same reason. Blending between siblings inside the group is untouched —
isolating draws a boundary, it does not switch blending off. `isolate` also keeps its ReactUnity-only
meaning of not inheriting ancestors' `opacity` and `pointer-events`.

`normal` costs nothing: an element allocates a render target and pays for the backdrop read only
once it actually blends, so a plain `filter` is exactly as cheap as it was. Isolating does allocate
one, since the containment is the capture.
