### Cascade layers are per document, and `revert-layer` works

**Every stylesheet in a context now shares one layer order.** A layer name meant a different layer
in each sheet before this, ordered only against that sheet's own layers, so `@layer utilities` in
your stylesheet and the same name in a framework's were two unrelated layers, and reopening one from
a second sheet made a new layer at the end instead of adding to the original. A layer now takes its
place from the first sheet that mentions it, wherever the rules for it arrive from — which is what
makes an `@layer theme, base, components, utilities;` statement in a sheet of its own do what it
looks like it does.

The order follows the sheets that are attached, so inserting or removing one settles it again.
Removing a sheet gives up the layers only it declared, and a sheet that declares `framework.reset`
slots that layer in ahead of `framework` — which moves `framework` itself along the order, so the
rules already in the layers that moved have their specificity worked out again.

**`revert-layer` is implemented.** It rolls a declaration back to the value it would have had if its
own layer had never been declared: the whole layer is passed over, not only the declaration that
reverted it, and if what it lands on reverts its layer too then that one goes next. In an unlayered
declaration there is no earlier layer to reach, so it rolls back past every rule of the same origin,
which is what `revert` does — and so does one in the earliest layer with nothing behind it. An
`!important` declaration reverts its layer at its own priority, where the layer order is reversed.

`revert` itself no longer throws in a framework that has nothing to read the previous value back
from, which is UIToolkit and the editor.
