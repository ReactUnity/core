### `rotate` turns clockwise on UGUI and reads the web's grammar

A positive `rotate` angle, and `rotate()`/`rotateZ()` in `transform`, used to turn a UGUI element
counterclockwise, because Unity's canvas has y up where CSS has y down. The same stylesheet now
turns the same way in both, which also puts Tailwind's `rotate-*` utilities the right way round.
`rotateX` still tilts the top edge away from the viewer, and `rotateY` now sends the right edge away
instead of toward it. UIToolkit already turned clockwise and is unchanged.

An animation or stylesheet that negated its angle to get the web's direction now needs the web's
sign. Fixes [#105](https://github.com/ReactUnity/core/issues/105).

The property also takes the values the web does: `none`, an axis keyword with an angle
(`rotate: x 90deg`), and an axis vector with an angle (`rotate: 1 1 0 45deg`), in either order.
`rotate3d()` in `transform` is `rotate3d(x, y, z, angle)`. A turn about a principal axis keeps the
angle as written, so a keyframe at `z 2turn` still animates two full turns. The older three-angle
spelling still reads as Euler angles, since it does not clash with any web form.
