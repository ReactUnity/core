### CSS logical properties

`padding-inline`, `margin-block`, `inset-inline-start` and the rest of the logical box properties
work, as longhands, as the two-value shorthands, and under their camelCase names in an inline style:

```css
#panel {
  direction: rtl;
  padding-inline: 4px 12px;
  margin-block-start: 8px;
}
```

`direction` is inherited, so setting it once turns the inline axis around for a whole subtree. The
block axis is always vertical, `writing-mode` not existing here. An inline property beats the
physical property covering the same edge whichever order the two are declared in, which is the one
place this differs from CSS and the reason not to set both on one edge. Under UIToolkit the inline
axis is always the physical one, since UIElements ignores `direction`.

The React Native spellings `padding-start`, `margin-end` and `border-start-width` reach the same
edges, and now do something for the first time.

Tailwind writes every two-axis and start/end utility as a logical property, so `px-*`, `py-*`,
`mx-*`, `my-*`, `inset-x-*`, `border-x-*`, `ps-*`, `ms-*`, `start-*` and `space-x-*` all work.
