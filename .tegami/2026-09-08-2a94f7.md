### `text-decoration` is a real shorthand, and the line has a colour

`text-decoration` used to be a second spelling of `text-decoration-line`, so a component it could
not spell invalidated the whole declaration. `text-decoration: underline dotted red` — a common
Tailwind and shadcn idiom — lost the underline as well as the dots.

It is a shorthand now. The line and the colour are applied, and the style and thickness components
are read and dropped:

```css
a { text-decoration: underline red; }
a:hover { text-decoration: underline dotted 2px currentcolor; }  /* dotted and 2px are dropped */
del { text-decoration: line-through #888; }
```

`text-decoration-color` is the new longhand. It inherits, where the web's does not, because the line
rides on `font-style`, which does; a non-inherited colour would leave nested text underlined in the
wrong one. It defaults to `currentcolor`, which is what was drawn before.

Only the parts TextMeshPro can draw are honoured:

- **`text-decoration-style`** — `solid` is all there is. `dashed`, `dotted`, `double` and `wavy`
  parse and are ignored.
- **`text-decoration-thickness`** — the thickness comes from the font asset's own metrics, so a
  length, `auto` and `from-font` are ignored.
- **`overline`** and **`blink`** are not accepted at all, and a declaration asking for one is
  dropped.

Two things follow from `solid` no longer standing in for `underline`. `text-decoration-line: solid`
is now correctly invalid, and `font-style: solid` with it. And because `font-style` carries italic,
bold and the letter casing as well as the two lines, the shorthand writes only the components
actually named — `text-decoration: red` sets the colour and leaves the line alone, where CSS would
reset it — so it cannot clear an inherited `font-style: italic`.

A colour that differs from `color` is drawn by wrapping the text in TextMeshPro's `<u color=…>` or
`<s color=…>`. That is invisible from the outside: `textContent`, `Content` and `:empty` all still
see the text itself, and the tags are skipped when `richText` is off.
