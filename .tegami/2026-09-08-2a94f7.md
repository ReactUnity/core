### `text-decoration` is a real shorthand, and the line has a colour

`text-decoration` used to be a second spelling of `text-decoration-line`, which meant every part of
the value reached the line converter and one it could not spell invalidated the whole declaration.
So `text-decoration: underline dotted red` -- a single common Tailwind and shadcn idiom -- lost the
underline as well as the dots. `text-decoration: underline solid` was the one variant that worked,
and only because `solid` had been mapped in as a synonym for `underline` to make it work.

It is a shorthand now. The line and the colour are applied, and the style and thickness components
are read and dropped:

```css
a { text-decoration: underline red; }
a:hover { text-decoration: underline dotted 2px currentcolor; }  /* dotted and 2px are dropped */
del { text-decoration: line-through #888; }
```

`text-decoration-color` is the new longhand, and inherits -- where the web's does not -- because the
line itself rides on `font-style`, which does inherit; a non-inherited colour would leave nested text
underlined in the wrong one. It defaults to `currentcolor`, which is what was drawn before, so
nothing changes for a stylesheet that does not set it.

Only the parts TextMeshPro can draw are honoured, and the shorthand's job is to stop the rest from
taking the line down with them:

- **`text-decoration-style`** -- `solid` is all there is. TMP has no dashed, dotted, double or wavy
  form, so those keywords parse and are ignored rather than rejected.
- **`text-decoration-thickness`** -- the line's thickness comes from the font asset's own metrics,
  shared by every element using that font, so a length, `auto` or `from-font` is also ignored.
- **`overline`** and **`blink`** are *not* accepted, because nothing can draw them at all. A
  declaration asking for one is invalid and dropped, as before.

Two things follow from `solid` no longer standing in for `underline`. `text-decoration-line: solid`
is now correctly invalid, and `font-style: solid` with it. And because `font-style` is the one
property carrying italic, bold and the letter casing as well as the two lines, the shorthand writes
only the components actually named -- `text-decoration: red` sets the colour and leaves the line
alone, where CSS would reset it -- so it cannot clear an inherited `font-style: italic`.

A colour that differs from `color` is applied by wrapping the text in TMP's `<u color=…>` or
`<s color=…>`, since TMP has no per-element decoration colour. That is invisible from the outside:
`textContent`, `Content` and `:empty` all still see the text itself, and the tags are skipped
entirely when `richText` is off, where they would draw as characters.
