### `:is()`, `:where()` and `:not()` take a complex selector anywhere

`:is()` and `:where()` were rewritten away by inlining their argument, and the two forms that
cannot be inlined -- one that does not begin its compound with an argument spanning a combinator,
and one inside another functional pseudo-class -- were left in the selector and matched nothing.
The first of those is `.dark\:x:where(.dark, .dark *)`, which is what Tailwind v4 emits for the
class-based dark variant the docs recommend; the second is `:not(:is(.a, .b))`. Both are matched
now, as a selector part that walks the tree from the element the way a rule's own chain does, at
the specificity of the most specific argument or none for `:where()`. `:not()` takes a complex
selector through the same part, so `:not(.a .b)` works too; it used to read `.a .b` as one class
name with a space in it.

### `:state(name)`

The standard spelling of a custom state. A bare unknown pseudo-class was already one -- `:busy`
matches while a state named `busy` is started on the element -- and it still is, but it warns once
about the name in case it was a typo. `:state(busy)` says the state is meant, and does not.

### `::-webkit-scrollbar` and the other web spellings of the parts

`::scrollbar`, `::scrollbar-thumb`, `::placeholder` and `::selection` were already the parts an
input and a scroll view expose. `::-webkit-scrollbar`, `::-webkit-scrollbar-track`,
`::-webkit-scrollbar-thumb`, `::-webkit-input-placeholder`, `::-moz-placeholder`,
`::-ms-input-placeholder` and `::-moz-selection` now name the same elements, so a stylesheet
written for a browser styles them without being rewritten.

### `@custom-media`

`@custom-media --name query;` names a media query list, or `true` or `false`, for use as a feature:
`@media (--name)`. A name is looked up when the query is evaluated, over every attached stylesheet,
so it can be declared in any sheet before or after its use and can come and go; the last
declaration wins. A pair of names that refer to each other is a cycle, and matches nothing. The
parser keeps an unknown at-rule as text, which is all the rule needs, so ExCSS is untouched.

### `@container scroll-state()`

`container-type: scroll-state` used to parse and decide nothing; now `scroll-state(scrollable: edge)`
reads such a container and holds while it can still scroll towards the edge -- `top`, `bottom`,
`left`, `right`, their logical names, the `x`/`y`/`inline`/`block` axes, `none` for a container
scrolled as far as it goes in every direction, or bare `scrollable` for any edge. Features combine
with `and`, `or` and `not`. The container's scrollable edges are tracked the way a size container's
content box is, and a change to them after layout restyles the subtree; a position that only moves
within the same edges restyles nothing. `stuck` and `snapped` parse and never hold, since nothing is
sticky and nothing snaps.

`ContainerType` is a flags enum now, `ScrollState` alongside the size types, and the renderer's
`containerType` type accepts the combined spellings.

### `@supports selector()`

Answered instead of always false: one complex selector is supported when every part of it parses
to something this engine matches, every pseudo-class is known or a state the framework has a
handler for (`:state()`, `:enter` and `:leave` always count), and every pseudo-element is one some
element has. A selector list, a relative selector, `:popover-open` or `::marker` are not. The
parser used to drop a `@supports` rule whose prelude began with a function, since its condition
grammar has no node for one; the ExCSS fork now keeps such a prelude as written, its seventh change.
