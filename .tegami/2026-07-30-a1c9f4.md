### Run a Vite dev server, entry document and HMR patches included

Pointing `DevServer` at a Vite server root now works on every engine.

A dev server answers its root with an HTML entry document rather than JavaScript — Vite's is a bare `<script type="module" crossorigin src="/assets/index.js">` — so the engine was handed markup. That content is now detected and its script tags are run. Only the scripts: the rest of an index.html describes a browser page. It does not go through `HtmlParser`, which is strict XML and rejects ordinary HTML5 (Vite's valueless `crossorigin` alone was enough to fail the load); an explicit `ScriptSourceLanguage.Html` source still parses as before.

The check prefers a declared type over a guess: the response `Content-Type`, then the extension, and only sniffing the first character when neither exists — which is the usual case for a `TextAsset` or an extensionless resource. Content-Type deliberately outranks the extension, because Vite's SPA fallback answers `/index.js` with the entry document.

**Jint and QuickJS now execute real ES modules.** Both were accepting `JavascriptDocumentType.Module` and parsing as a script regardless, which is why `import.meta` and `export` failed on them. Jint 4 goes through `Engine.Modules`, QuickJS through a module eval that was already in the binding but never reachable. QuickJS also only filled in `import.meta` for modules that arrived via its loader, leaving `import.meta.url` undefined on a module evaluated straight from source; it is now compiled first so the url can be set before the body runs. Module-shaped bundler output is therefore run as a module rather than rewritten, and nothing rewrites module syntax any more.

Executing a module is not the same as resolving one, so those are separate capabilities. Jint and QuickJS resolve specifiers only through a local file system, and Vite's HMR client applies every patch with `import(url)` against the dev server. Dynamic imports on those two engines are pointed at a host loader that fetches the chunk and executes it; ClearScript, which has an HTTP document loader already, is left alone.

`build.rollupOptions.output.format: 'iife'` must be scoped to `command === 'build'`. `experimental.bundledDev` bundles the dev server output with the same options, and under iife rolldown rewrites `import.meta` to `{}`, which makes Vite's HMR client throw on `new URL(import.meta.url)` before it opens its socket — the connection dies silently at `[vite] connecting...`, in browsers too. The Kitchen Sink config shows the shape.
