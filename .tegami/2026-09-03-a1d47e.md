### A mounted `<style>` could be collected out from under its own updates

Toggling a `<style>` off — unmounting it, or setting `active={false}` — sometimes did nothing, leaving the stylesheet applied for the rest of the session. It looked like a propagation delay and was not: the update never arrived at all, no matter how many frames it was given.

`<style>`, `<script>` and `<html>` are `ProxyComponent`s, and a proxy component never enters the component tree itself. Its `SetParent` delegates to the component it wraps, so what lands in the parent's `Children` is that inner component — for `<style>` and `<script>` a `NoopComponent`, which only records a parent and registers nothing at all. Either way the proxy is unreferenced, leaving `ReactContext.Refs` as the only thing pointing at a mounted one, and it holds `WeakReference`s on purpose. A managed collection between mounting the element and updating it dropped the component, `GetRef` returned null, and `applyUpdate` — which returns silently on a null instance — discarded that command and every later one for the same ref.

A proxy component is now held for exactly as long as it is parented, which is what `Children` already does for everything else.

It surfaced as a flake in `StyleComponentTests` under QuickJS alone, which is a detail of *when* the collection happens rather than of any engine: `ScriptRuntime.Shutdown` calls `GC.Collect` twice, so a QuickJS engine teardown forces a full collection that the other two never ask for. Forcing one by hand fails the same tests on Jint and ClearScript identically, which is what the new `StyleTagIsNotCollectedWhileMounted` does.
