### `width: 100%` no longer collapses inside a content-sized parent

A percentage cross size resolved to zero whenever the parent's size came from its
children -- [#89](https://github.com/ReactUnity/core/issues/89). A `width: 100%` divider
under a column that had no width of its own simply disappeared, and the two things that
made it come back, `align-self: stretch` and a pixel width, are the two paths that happen
to lay the child out a second time.

The parent is measured from its children first, and a percentage contributes nothing to
that measurement -- correct, and what the web does too. What was missing is the other
half: nothing resolved the percentage against the size that measurement produced, so the
child kept its intrinsic answer. Yoga now does, and eight of the nine layouts that
reproduced this are exact against Chrome. The ninth is a percentage on the *main* axis,
which is [facebook/yoga#1661](https://github.com/facebook/yoga/issues/1661) and untouched
here.

The fix is one commit on top of Yoga's current `main`, carrying seven regression tests of
its own; Yoga's other 849 tests pass with it. `PercentageSizeTests` covers it from this
side, on all three engines -- against the binaries this replaces, it reports the `0` the
issue described.

### The Yoga binaries are now built from a recipe in this repo

Every native `yoga` artifact came from a workflow living inside the ReactUnity fork of
Yoga, so the recipe was never reviewed beside the C# that consumes it and nothing
recorded which commit produced a given binary. [native/yoga](https://github.com/ReactUnity/reactunity/tree/main/native/yoga)
is that recipe now, in the same shape `native/quickjs` already used: one CMakeLists that
fetches Yoga at a pinned SHA, a `native-yoga` workflow that builds all nine artifacts and
commits none of them, and a `PROVENANCE.md` beside the binaries naming the commit they
came from.

**The fork is down to that one commit.** Everything else it carried was build
configuration, and building the target here rather than including Yoga's own CMakeLists
sets all of it directly -- so what ReactUnity ships that upstream does not is now a
one-line `git log`. The binaries move from a 2022 branch point to current `main` with it.

The same change drops the three binding layers ReactUnity never calls. WebGL is the
visible one: the shipped archive was built through Yoga's embind project and carried 1191
symbols and 531 KB into every player, against 497 symbols and 256 KB for the same C API
compiled straight from source.

Android changes shape with it -- a single `yoga.aar` becomes one `libyoga.so` per ABI,
the layout `com.reactunity.quickjs` already uses, and one library rather than the two the
`.aar` carried. Checked on an emulator against the arm64 build, where it lays out
identically to the Windows one; not yet on real hardware.

Two checks come with it. `check-exports.py` proves the library exports all 132 names
`Native.cs` P/Invokes, on every platform, from whichever runner built it.
`check-enums.py` proves the C# enums still agree with `YGEnums.h` -- enums cross the
boundary as bare ints, so a member that shifts by one links fine and lays out the wrong
thing.

It caught two on this upgrade. Upstream inserted `YGJustifyAuto` at the front of
`YGJustify`, moving every member below it; without the check, `justify-content: center`
would have started meaning `flex-end`. And `YogaExperimentalFeature` still declared
`AbsolutePercentageAgainstPaddingEdge` and `FixAbsoluteTrailingColumnMargin` after Yoga
removed both -- passing either indexed a `std::bitset<1>` out of bounds and threw C++
across the P/Invoke boundary. Both are fixed.
