### A dev server can be restarted under a running app again

Vite's HMR client polls for a restarted dev server and reloads once it answers, and none of that
worked: the first thing it did was throw `TypeError: not a function`, and fixing only that moved the
failure rather than removing it. Three pieces were missing.

`document` is an event target now -- `addEventListener`, `removeEventListener` and `dispatchEvent` --
and reports `visibilityState` as `"visible"` with `hidden` false. Those two are constants on purpose:
the poll parks itself while the document is hidden, so driving them from Unity's focus state would
stall a dev-server restart for as long as the Editor sat in the background.

A `WebSocket` whose connection is refused reports `error` before `close`, as a browser does.
WebSocketSharp raises no error at all for a failed connect -- only an abnormal close, code 1006 --
and the ping that tests whether the server is back settles on `open` or `error`, so it waited
forever on the first one.

And `EventTarget` dispatches over a copy of its handler list. A handler that removes a listener is
ordinary DOM usage -- that ping drops both of its own from inside whichever fires first -- and doing
it mid-dispatch threw `Collection was modified`.
